## nginx 冲突修复（同日追加）：宽泛 /api/v1/ 前缀劫持 gakiwoo 登录

- **事故**：恢复 nginx location 后用户反馈"另一个项目无法登录"
- **根因**：gakiwoo-api 自身挂载 `/api/v1` 前缀（server.js: `app.use('/api/v1', v1)`，含 `/api/v1/auth/*` 登录接口）；我们此前用宽泛 `location ^~ /api/v1/` → :3001，把 `/api/v1/auth/login|me` 劫持到 foodcalorie-api → 404「接口不存在」→ 另一项目登录失败
- **修复**：location 收窄为 `^~ /api/v1/foodcalorie/`（我们的业务前缀）→ :3001 + 精确 `= /api/v1/health` → :3001；`/api/v1/auth/*`、`/api/auth/*` 及其它全部交还 gakiwoo(:3000)
- **验证通过**：/api/v1/foodcalorie/records=401（我们）、/api/v1/health=200（我们）、/api/v1/auth/me=LOGIN_REQUIRED（gakiwoo 恢复）、/api/v1/auth/login 测试账号返回 user（登录恢复）
- **运维纪律**：恢复脚本归档为 `archive/scripts/nginx_deploy_narrow.py`（收窄版）；旧宽泛脚本改名禁用 `nginx_deploy_broad.LEGACY-DO-NOT-USE.py`；README 已写入三条警示
- **经验**：nginx 前缀 location 一定要收窄到自己的业务前缀，绝不能挡别人已挂载的路径；恢复线上路由时先确认对方服务挂载了哪些前缀

### 关键坑（P0 部署踩的，务必记住）
- **静态 location 必须 `^~`**：gakiwoo.com 有正则 location（如 `~* \.js$`），前缀 location 会被正则抢走静态资源 → JS/CSS 404；加 `^~` 后修复
- **nginx 备份绝不可放 sites-enabled/**：include 会加载所有 `*` 文件（含 .bak.*）→ nginx -t 报错（备份里有损坏配置时直接挂）
- **paramiko run() 返回 (stdout, stderr)**：`_, out = run(...)` 会把 out 取成 stderr → 空输出误判；应 `out, _ = run(...)`
- **sed 删 nginx location 行会留孤儿块**（块内 alias/index/try_files 悬空）→ 语法错误；删除 location 应整块正则删除
- **python -c/heredoc 嵌多行含单引号字符串必炸** → 一律用 Write 写脚本文件执行
- 外网登录后 pathname 是 `/foodcalorie`（无尾斜杠），断言注意
